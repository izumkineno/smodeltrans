# smodeltrans UI 重设计总览

> 文档状态：设计交接稿
>
> 适用范围：主工作台、六个主页面、实时字幕浮层、快捷翻译框及相关交互约束
>
> 当前实现基线：Tauri 2 + Vue 3.5 + TypeScript + Naive UI

## 1. Design Read

将 `smodeltrans` 理解为一款 Windows 本地翻译工作台。核心用户需要持续阅读游戏、视频或桌面应用中的字幕，同时偶尔处理文本和图片。

设计语言应满足：

- 译文优先，结果先于实现细节。
- 操作即时，运行状态持续可见。
- 信息密度可控，不把所有配置做成等权卡片。
- 适合中文、英文、日文等 CJK 与拉丁文字混排。
- 主工作台强调结构，透明浮层强调对比度和可读性。

## 2. 当前产品拓扑

```text
主工作台
├── 实时翻译        一级主任务
├── 工具
│   ├── 文本翻译
│   ├── OCR
│   └── OCR 翻译
└── 系统
    ├── 设置
    └── 模型监控
```

路由定义位于 [`src/app-router.ts`](../src/app-router.ts)，当前包含：

| 路由 | 页面 | 产品角色 |
| --- | --- | --- |
| `/live-translation` | 实时翻译 | 持续运行的核心任务 |
| `/translate` | 文本翻译 | 一次性文本处理 |
| `/ocr` | OCR | 一次性图片识别 |
| `/ocr-translate` | OCR 翻译 | 一次性图片识别与翻译 |
| `/settings` | 设置 | 模型和全局偏好准备 |
| `/model-monitor` | 模型监控 | 运行时诊断和模型驻留控制 |

页面详细需求见 [`UI_REDESIGN_PAGES.md`](./UI_REDESIGN_PAGES.md)。

浮层和辅助窗口需求见 [`UI_REDESIGN_OVERLAYS.md`](./UI_REDESIGN_OVERLAYS.md)。

设计 token、交互状态、无障碍和验证约束见 [`UI_REDESIGN_SYSTEM.md`](./UI_REDESIGN_SYSTEM.md)。

## 3. 重设计目标

### 3.1 让实时翻译成为打开应用后的第一任务

首屏应直接回答三个问题：

1. 要翻译哪个窗口？
2. 要翻译成什么语言？
3. 如何开始或停止当前会话？

目标窗口、目标语言、开始按钮和当前会话状态应处于首屏。显示样式、提示词、识别算法和诊断记录属于第二层或第三层。

### 3.2 建立统一的一次性工作流

文本翻译、OCR、OCR 翻译应共享相同的结构语言：

```text
输入或上传 → 预览或编辑 → 处理进度 → 结果 → 复制、保存、重试
```

取消和错误不能清空用户输入或预览。重试必须是可见且可理解的下一步动作。

### 3.3 区分快捷翻译框与实时字幕框

当前 [`LiveSubtitlePanel.vue`](../src/components/LiveSubtitlePanel.vue) 同时服务实时字幕和快捷翻译。重设计时应保留共享内容结构，但增加明确的视觉变体：

- 快捷翻译框：短时、快速阅读、译文优先、无实时调节工具栏。
- 实时字幕框：持续运行、可拖动、可重选 ROI、可调尺寸和显示方式。

不要把实时字幕工具栏缩小后直接放进快捷翻译框。

### 3.4 把设置和诊断从主流程中降级

设置页负责准备和持久化配置，模型监控页负责运行时观察。两者可以信息密度较高，但不应把模型路径、采样参数和运行指标带入普通翻译页的首屏。

## 4. 当前平台约束

主窗口配置位于 [`src-tauri/tauri.conf.json`](../src-tauri/tauri.conf.json)：

- 默认尺寸：`1180 × 760`
- 最小尺寸：`720 × 560`
- 无系统装饰
- 自定义 titlebar 和窗口控制
- 主窗口侧栏当前宽度：`208px`
- `720px` 宽度附近需要提供侧栏隐藏后的替代导航

快捷翻译窗口约束：

- 初始尺寸：`320 × 104`
- 最小尺寸：`160 × 72`
- 透明
- always-on-top
- skip taskbar
- 不可调整大小
- 根据内容动态调整窗口尺寸

这些约束决定了主 UI 和浮层不能使用同一套布局策略。

## 5. 不应改变的行为契约

重设计只改变布局、层级、视觉和交互表达，不应破坏以下行为：

- 实时翻译的 `idle`、`selecting`、`warming`、`running`、`paused`、`stopping`、`error` 状态。
- 一次性页面的 `idle`、`preview`、`processing`、`result`、`cancelled`、`error` 状态。
- 取消后保留输入或图片预览，并允许重试。
- 目标语言、实时显示、识别、翻译提示词和快捷键配置的持久化。
- 实时状态、字幕、进度、区域框和调试记录的 Tauri event bus 传递。
- 浏览器预览与 Windows Tauri 桌面端能力差异提示。
- Esc 关闭快捷翻译框或取消区域选择。
- 无边框窗口的拖拽区和窗口控制区。
- `region_replace` 模式的目标客户区坐标 1:1 关系。

## 6. 推荐实施顺序

### P0：先解决主层级和浮层差异

1. 重做主壳层的导航和页面首屏层级。
2. 重做实时翻译页的会话准备和运行控制。
3. 为 `LiveSubtitlePanel` 增加 quick/live 明确变体。
4. 先完成快捷翻译框的译文优先、动态尺寸和长文本约束。

### P1：统一一次性工具页面

1. 抽象文本、OCR、OCR 翻译的输入到输出视觉结构。
2. 统一进度、取消、错误、重试、复制和保存的表达。
3. 将快捷翻译配置改为设置页中的独立全局区域，并在文本翻译页保留紧凑状态入口。

### P2：整理系统页面

1. 设置页按常用配置和高级配置重新分组。
2. 明确每个配置的作用范围和生效时机。
3. 保持模型监控的运维属性，优化数据层级和表格可读性。

## 7. 设计交付物建议

实施前建议形成以下设计资产：

- 主工作台页面布局稿
- 实时翻译页面的 idle、running、paused、error 状态稿
- 快捷翻译框的 processing、result、error 状态稿
- 实时字幕框的 toolbar hover、focus、pinned 状态稿
- light、dark 两套 token
- 1180x760、720x560、320x104、160x72 关键尺寸稿
- CJK 长文本和多行文本样例

所有页面最终应以 [`UI_REDESIGN_SYSTEM.md`](./UI_REDESIGN_SYSTEM.md) 中的共享约束为准。
